# 参考图与 Blender 验收闸门

在生成参考图、制作 Blender blockout、调整材质灯光或批准动画预览时读取本文件。

## 共同原则

- 把参考图当作视觉目标，把 Blender 中可测量的状态当作事实来源。不要用像素级相似度要求 3D 场景机械复制 AI 图片。
- 每次只修正一个明确问题，保存修正前后的预览和测量结果。
- 为每个镜头更新 `shot-status.json`；聊天描述、MCP 成功返回和单张截图都不能代替持久化证据。
- 只允许 `pending`、`pass`、`fail`、`accepted_deviation` 四种闸门状态。只有用户明确接受偏差时才使用 `accepted_deviation`。
- 确定性工具不可用时，使用 Blender 脚本、渲染叠图或人工可复核的替代检查，并记录方法；不要把“未检查”写成通过。

`shot-status.json` 至少使用以下结构：

```json
{
  "shots": [
    {
      "shot_id": "shot_01",
      "gates": {
        "reference_ready": {"status": "pending", "evidence": []},
        "blockout": {"status": "pending", "evidence": []},
        "lookdev": {"status": "pending", "evidence": []},
        "camera_animation": {"status": "pending", "evidence": []}
      },
      "issues": [],
      "next_action": "",
      "updated_at": ""
    }
  ]
}
```

## A. 参考图就绪

逐镜头检查：

- 文件可完整解码，画幅和方向符合 `storyboard.json`。
- 使用已批准母图和同一 `STYLE_CAPSULE`，没有未解释的风格漂移。
- 画面只表达一个镜头，不包含拼贴分镜、字幕、片名或生成式 UI。
- 主体、环境、时间、光向、景别和摄像机方向与分镜一致。
- 主体身份、关键道具、材质语言和空间规则在镜头之间连续。
- 图像明确表达 Blender 需要复现的轮廓、比例、遮挡和构图；无法从单图判断的背面或结构另列为假设，不让模型自行补成事实。
- `generation-manifest.json` 已记录模型、提示词、输入参考、尺寸、输出路径和可获得的任务标识。

任一镜头不通过时，只重做该镜头；全片风格漂移时回到母图，不靠追加形容词逐张补救。

## B. Blockout 对照

先从目标摄像机渲染定帧，再按需要补正交、侧面或斜侧辅助视角。检查：

- 主体画面占比、视觉中心和有意裁切符合该镜头的 `acceptance_checks`。
- 没有意外出框、遮挡、穿插或近裁剪面切割。
- 主轮廓、地平线、消失方向、前中后景层次与参考意图一致。
- 关键物体的尺寸、间距、接触、对齐和比例可由 Blender 场景测量支持。
- 摄像机焦段、位置、旋转和传感器设置已记录；不要用对象变形掩盖错误透视。
- Collection、对象和摄像机使用语义化名称，活动镜头与当前帧正确。

先通过构图和比例再增加细节。AI 参考存在不可能透视时，保持物理可信，并把偏差记录为有理由的设计决定。

## C. 材质与灯光对照

在 blockout 通过后检查：

- 主色、辅色、明度层级和材质粗糙度符合 `style-lock.md`。
- 主光方向、色温、阴影软硬、轮廓光和雾的层次与风格母图一致。
- 主体与背景有足够明度或色相分离，关键轮廓没有被反射、高光或雾吞没。
- 材质尺度一致，没有明显拉伸、闪烁、摩尔纹或与交付分辨率不匹配的高频细节。
- 色彩管理、曝光和查看变换在所有镜头中一致；镜头级偏移必须有叙事理由。

## D. 摄像机与动画对照

使用低分辨率 playblast 检查首帧、中段、落定帧和末帧：

- `subject_action` 与 `camera_action` 各自只有一个主要意图，运动方向清晰。
- 加速度、停留帧和切点符合分镜；关键信息落定后保留 `hold_frames`。
- 摄像机没有意外抖动、速度突变、穿模、裁切或焦点漂移。
- 跨镜头的主体位置、运动方向、光线和空间关系保持连续，或有明确的断裂意图。
- 若使用音乐，关键动作和切点位于批准的节拍帧，允许误差写入验收条件。

## 迭代与放行

每轮按以下顺序执行：

1. 从当前闸门列出最多三个可观察差异。
2. 选择影响最大的一个差异，并定位到几何、变换、材质、灯光、摄像机或动画。
3. 保存检查点，只修改对应参数。
4. 使用同一摄像机、帧号和测量方法重新生成证据。
5. 更新 `shot-status.json`，通过后再进入下一闸门。

同一问题连续两轮没有改善时，停止微调并检查父子层级、未应用变换、约束、驱动器、摄像机绑定和场景帧。所有必要检查为 `pass` 或经用户明确接受为 `accepted_deviation` 后，镜头才可进入正式渲染。
